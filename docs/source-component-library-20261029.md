# 独立原始源码构件库

本次将编辑面板“原始源码构件”从当前文档的节点枚举，改为单独发布的源码语义构件库。打开空白模型、切换案例、导入外部文档时，库内容保持一致。

## 整理结果

| 项目 | 数量 |
| --- | ---: |
| 构建时扫描的已迁移模型资料 | 43 |
| 可复用模块和算子实例 | 962 |
| 简短名称下的分类条目 | 100 |
| 保守结构指纹 | 196 |
| 去重后具体版本 | 262 |

100 类包括 60 类模块和 40 类算子。相同名称下的不同结构、不同构造参数保留为版本；完全相同的事实指纹归并来源。262 个具体版本相对 962 个实例减少约 72.8%。这是静态源码语义图的保守匹配，不声称任意 Python 程序等价。保留节点原有顺序，暂不对重排后的图做同构推断，因此仍可能保留未归并的等价实现。

构件卡片和插入后的模块使用 Linear、Conv2d、MultiHeadAttention、PositionwiseFeedForward、EncoderLayer 等源码标识，不将源码名称翻译成中文；不显示长节点身份、调用路径或实例序号。原始类名/框架名称继续参与搜索。结构与参数版本在卡片内选择，来源与参数在详情中查看；同名结果优先于内部包含该构件的模型。

变量别名、输入输出接口、资源节点、条件分支、重复次数外框和仅有运行观测的节点不作为独立库条目。它们作为模块内部的必要事实保留；运行记录不随新构件传播。基础构件与当前文档的“我的组合模块”继续有各自入口。

## 独立资源与 API

- `studio/public/preview/data/source-components/index.json`：独立库索引，schema 为 `archcanvas-source-components/1`。
- 同目录 `src-<指纹>.json`：每个具体版本一个 `semantic-module/1` 资源。包含完整子图、必要资源、接口、来源描述和归并实例位置，不引用当前打开文档作为运行依赖。
- `scripts/build_source_component_library.py`：显式构建工具；只读取正式工程内已迁移资料，不调用 prototype 程序或其 Python 环境。构建输入选定后，运行时不扫描或提取预设案例。
- 面板只在展开库时读取索引；仅在加入时读取所选构件。列表按每次 20 类展示，减少 DOM 与首屏开销。全部资源约 32.6 MB，不一次加载。
- 编辑请求 `{action:'add', sourceComponent:'src-…'}` 由 iframe 根据独立索引解析，并检查身份、资源路径、字节数、SHA-256 和 IR 结构。请求不能指定任意文件路径。
- 插入时沿用 Summary 原生 authoring 的身份重映射与槽位协议。插入资源和来源写入编辑稿，编辑 JSON 恢复不需要再次读取构件库或案例文件。
- 原 `sourceNode` API 和高级“原始构件精确重建”保留，继续服务当前参考稿的精确重建；它们不再用作全局库 UI 的数据来源。

外部连接被转换为显式模块接口，保留内部 producer/consumer 槽位和共享输入的扇出。已有的模块输入输出接口直接复用，不重复包装。抽取算子时携带其读取的参数资源，不把该资源在原模型中对其他调用的依赖错误暴露为新模块输出。原始源码节点身份、位置、表达式和文件摘要保留供追溯；插入与复制不写回 Python。

此库保存的是可组装的源码语义构件，而不是经过运行验证的独立 Python 源码包。历史模块绑定、共享声明和契约在组装 IR 中继续按现有规则降为来源事实；不将新组装图伪装成原程序的执行证明。

## 验证

- Python 5 项检查通过：改名后的重复归并、参数与算子差异、精确槽位、必要资源、共享资源的边界、已有接口不重复、运行节点排除、全部生成资源逐字节可复现。
- 34 项相关前端与 Summary 编辑回归检查通过。新增检查覆盖全部 262 个资源的 SHA-256 / 字节数 / IR 结构、空白稿插入、重复插入身份隔离、完整保存恢复、来源随稿携带、错误身份和损坏内容拒绝、搜索与分页。最终改动涉及的 15 项检查再次通过。
- `npm run build`、`npm run audit:preview`、`git diff --check` 通过；集成资源清单与文件内容一致。构建仍有现有主 JS 包体积提示。
