# Python 执行等价验证与悬浮源码工作台

本轮把“IR 结构重建”推进到了实际 Python 生成和 CPU 执行。这里的生成有两个明确范围：保留完整源码的精确重建，以及通过模块接口连接、内部未修改的源码构件组合。没有实现任意原子图到任意 Python 程序的自动合成；5 个样例通过也不证明所有 Python 程序等价。

## 5 个现有模型的执行证据

使用正式工程内的测试源码副本、当前静态解析器和 Studio 实际使用的 `SemanticAuthoring`。过程为：读取源码 → 绑定当前 IR → 空文档 → 逐个加入模块/原子构件 → 恢复跨构件端口 → JSON 保存恢复 → 后端重新解析源码、核对全部节点和依赖 → 生成新的 Python 文件 → PyTorch CPU 执行比较。

| 现有模型 | 原案例 ID | 覆盖的行为 | 比较次数 |
| --- | --- | --- | --- |
| BranchMLP | 4ab8c787e32daeac | 两条布尔分支 | 24 |
| TinyCNN | 9e10a966b99ab3ef | 卷积、激活、池化、展平 | 12 |
| ReusedRecurrent | 61b219f6938bacfb | LSTM 状态、嵌套元组、同一 Linear 的共享别名 | 12 |
| VectorResidual | d188e6e78567c2cd | LayerNorm、嵌套模块、Dropout、残差 | 12 |
| ConditionalResidual | 43822e6ee9898ff3 | 多输入、条件分支和残差 | 24 |

合计 84 次，覆盖模块/原子两种重建、eval/train、随机种子 17/41/89、条件模型的两个分支。使用相同权重，执行前分别重置随机状态。输出、输入梯度、参数梯度和 state_dict 均以 rtol=0、atol=0 比较通过；最大输出误差为 0。ReusedRecurrent 额外检查 `shared is alias`。环境为独立的 ArchCanvas conda 环境，PyTorch 2.7.1+cu118，CPU，单线程；正式服务本身无需安装或导入 PyTorch。

证据位于 `docs/evidence/python-execution-20261029/`，包括机器可读的 `execution-report.json` 和每个模型两种重建生成的 `.py`。测试入口为 `tests/test_summary_python_execution.py`；前端使用同一 `authoring-model.js` 的重建驱动为 `studio/scripts/rebuild-python-document.mjs`。两份原始测试源码及迁移理由、哈希见 THIRD_PARTY_NOTICES.md；运行不依赖 prototype 目录。

旧归档 IR 的运行观测节点不作为源码结构比较对象。ReusedRecurrent 的旧归档有两条元组拆包边使用 `out`；当前解析器使用正确的 `0` / `1`。本轮比较的是同一现有模型经当前解析器重新绑定后的 IR，再精确重建。该差异写入 execution-report.json 的 catalogOperandUpdates，没有把旧归档的端口直接当作可执行证据。

额外验证了独立构件的真实新组合：两个都名为 Block 的源码分别放入独立 Python 文件，顺序 `(x+2)*3` 在 x=1 时产生 9，重接后 `x*3+2` 产生 5。缺失连接、修改源码构件内部、缺失构造参数和不完整参考重建均拒绝生成。源码含顶层 raise 的测试确认识别、解析和生成均不执行用户代码；ZIP 内的 Python 字节也与生成结果一致。

## 源码工作台与交互

在编辑模式的“模型构件”顶部点“打开悬浮源码工作台”。窗口通过 portal 独立悬浮，不遮罩或冻结画布；标题栏可拖动，右下角可调整大小，并约束到可见视口。关闭后，在当前编辑副本中重新打开会保留文本。完整模型的源码、入口、构造参数随文档保存，重开副本时也能恢复。

Monaco Editor 0.57.0 按需加载，仅打包 Python 语言和所需编辑动作。提供语法高亮、行号、括号颜色、代码折叠、自动缩进、Tab/Shift+Tab、2/4/8 空格设置、Tab 转空格、自动换行、查找和撤销。它使用 VSCode 的编辑器内核，但没有接入 Pylance、Python LSP 或项目环境类型检查，不宣称具备完整 VSCode Python 扩展能力。内嵌浏览器使用 Monaco 标准文本输入模式，避免新 EditContext 输入机制的兼容问题。

“识别入口与模型结构”通过独立的受限 AST worker 检查 nn.Module 类、类间构造依赖、组合入口、forward 参数及构造默认值。单一组合根会被推荐为完整模型；多个根不会静默选第一个。辅助类、imports 和常量保留在源码中。类和模块本身没有绝对的语法区别，因此推荐是结构建议；用户可明确选择“作为构件加入当前模型”或“作为完整模型打开新副本”。语法错误显示行列信息。必填构造参数会被提示。

完整模型导入先完成解析和原生视图校验，再安装新文档。解析期间工作区或文档变化会拒绝迟到响应，旧编辑稿保留。完整模型导入后继续停留在编辑模式。

浏览器已实际验证：粘贴含 EncoderBlock / VisionEncoder 两个类的模型 → 识别组合根 VisionEncoder → 推荐完整模型 → 缩进选项、Tab 转空格和换行 → 新副本显示嵌套模块 → 生成 Python。窗口窄屏越界和输入机制问题已通过实测修正。下载按钮已触发且无控制台错误；浏览器自动化未捕获 Blob 下载事件，因此下载落盘不作为已确认的浏览器证据，ZIP 内容已由后端测试独立核验。

## 导出和边界

编辑模式 → 高级 → 生成可执行 Python → 校验当前图并生成 Python。成功后可检查各文件并下载 ZIP，入口为返回的 `generated_model:build_model`（若原源码已有同名函数，工厂名自动避让）。导出只创建新文件，不改写原始 Python。

完整源码重建会重新编译所保存的 source/entry/constructor，并核对当前文档全部节点和依赖；图不同或重建未完成就拒绝。源码构件组合会重新核对每个构件的原始身份映射及内部结构，然后根据当前外部连线生成 nn.Module 调用和输入输出。构件源码分文件保留，避免同名类冲突。缺失输入、多驱动、环路、连接内部原子、未知原子、无源码构件和未支持的分组不会被忽略。

只有归档 IR、没有完整源码绑定的旧案例，仍需通过源码工作台导入其原始源码后才能导出。编辑单个内部原子的参数或计算表达式后，也需要重新解析对应源码。生成时只检查静态绑定和 Python 语法，不在服务端自动执行输入代码；用户源码所需依赖、设备、shape 和自定义副作用仍属于实际运行条件。保存的源码不是正式源码事务绑定，也不自动获得修改工程源码的权限。
