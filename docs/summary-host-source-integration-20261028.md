# host 快照来源共享与原生显式保存

日期：2026-10-28。继续按 Summary 为主的裁决，减少原生画布向 Studio 面板发布状态时对完整语义来源的重复复制。Studio 顶部菜单、折叠面板、正式 CAS/事务和 publication 合同保留。

## 本阶段替换

原 `studioDocument()` 分别对 graph、adapter、nativeDocument 执行 JSON clone，同一完整 IR 在一条状态消息中成为多份独立对象。当前使用 `studio-shared-source.js` 的来源池生成独立 JSON 快照：完整 `archcanvas-source-semantic/2` 的所有字段相等后共享冻结 IR，其余几何、相机、选区、面板状态和编辑声明独立复制。修改同一 digest 下的源码 span、运行 source stack、未知字段、数组顺序或字段存在性，都不会复用旧来源。

会话来源池继续只强保留四份来源；单次快照另有临时完整内容比较表。包含九种不同模块片段的编辑稿，即使复制中触发会话池淘汰，消息前后的同一原始 IR 仍共享；临时表在本次复制结束后释放，不扩大跨消息的缓存保留数。

只含同名 schema 的 `importedDocument` 是说明元数据，不是完整 IR；缺少 nodes/edges 数组时按普通状态复制。真实浏览器最初将该元数据计入 IR 个数，导致探针断言失败；诊断确认完整来源本已共享。随后同时收紧生产识别条件和探针，并补充“元数据仍独立可变”的反例。失败记录保留，不算通过。

`studioState()` 继续发布原有完整文档形状和字段，层级树、对象检查器、F0/F1 和源码映射无需维护第二张语义图。同一 `postMessage` 的 structured clone 保留 IR 对象间的引用共享；每条消息仍发送完整来源，本阶段没有跨消息缓存协议。

显式 `save` 改为在原生 graph 上直接调用 `N.snapshot()`，保留相机并写入现有 IndexedDB version 5；不再先构造整个 host 文档、再对其 graph 全量 JSON clone。自动保存、来源重新验证、撤销历史、编辑副本记录和正式 CAS 保存边界保持原合同。

实际截图还暴露了原有浏览器恢复分支遗漏：找不到正式 CAS 文档、改从浏览器重开时，没有读取已保存预览标记，导致图正确恢复却显示未保存。该分支现在在采用当前面板文档后核对保存标记；只有模型、文档对象和加载代数仍一致才更新“已保存”状态。缺失标记或核对期间切换模型仍保留未保存状态。针对实际 App 回调新增两项测试，浏览器新增刷新后可见“已保存”的断言。

## 数据与信任边界

共享只改变同内容不可变对象的引用，不赋予任何语义或源码写回权限。原始 IR、CPU 归档证据、opaque 边界、节点/端口身份和原生验证均保留；导入 JSON 仍经过 Summary 原始 reader、声明摘要、源码匹配、图元和物理路由验证。

便携 JSON 继续使用 `summary-merge-recursive/1`，包含全部原始内容；JSON 本身不保存共享引用，因此文件体积没有因为本阶段而减少。编辑副本 `record()` 和其他原生防御性复制仍有成本，不能把本阶段当作完整保存去重。

## 自主诊断与实际限制

`studio/scripts/profile-summary-host-source.mjs` 使用当前和删除前的实际 `studioDocument()`，分别构造三张受限大图的 F0 诊断快照。它比较完整 JSON 内容和实际 structured clone 引用，另用 Node V8 serialization 测量引用表示体积；该数据不是浏览器 IPC 字节、heap/RSS 或完整路由压力验收。

三图的完整 IR 从一条消息中的两份变为一份，引用表示体积分别减少约 28.9%、36.3%、34.6%。首次快照构建在这次运行中更慢，原因包括完整内容比较和 JavaScript 递归复制；这里不宣称延迟改善。诊断使用 300 ms F0 路由预算，仍有 pending/failed 路径，不能开放三个大图或提高 480 节点 / 3600 依赖 / 16 MB 的现有限制。

## 验证记录

专项执行实际 `studioDocument()` 和实际显式保存回调，覆盖完整内容比较、原始字段、独立几何/相机/状态、structured clone 引用、元数据反例和保存忙碌拒绝。相关来源共享、五类文档、组装、精简层级和保存状态回归一起执行。最初的 Node 反例使用带 `window` 的 VM，却从 globalThis 读取模块，已修正测试环境并保留失败日志。

真实 Chromium 检查父窗口实际收到的引用、F0/F1、原生编辑的 baseline、IndexedDB、便携 JSON 重导入和整页重开。另执行既有共享/Worker 故障恢复、原生视图及手势矩阵。构建、独立副本、当前资源摘要与最终数字记录在本阶段验证目录；不沿用其他阶段的通过数。

原生浏览器矩阵的一项旧反例通过 `structuredClone(portable)` 改 graph IR；共享引用生效后，这也改变同消息的 adapter IR，因此在更早的适配包内容校验处被正确拒绝，而旧测试只接受后续 graph 契约报错。现分别验证“共享图与 adapter 同时篡改”和“JSON 往返后仅篡改 graph”两条拒绝路径，未放宽来源验证。
