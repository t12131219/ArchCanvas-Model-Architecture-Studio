# Formal local Alpha runtime and bounded M3/M4 capabilities

The formal project now contains an independently written visual Alpha. The Skill distribution still contains instructions only: copying this Skill does not copy or install the runtime. Resolve the actual checkout or installation before using these commands.

From the formal project root:

```bash
PYTHONPATH=src python -m archcanvas_cli capabilities
PYTHONPATH=src python -m archcanvas_cli --help
PYTHONPATH=src python -m archcanvas_cli analyze --root fixtures/transformer --entry model:Transformer --output /tmp/archcanvas-transformer.json
```

`analyze --root PATH --entry module:Class` produces Architecture JSON. `analyze --source FILE --entry Class` handles an explicit single file. The stdlib AST frontend never imports or executes model code. Unsupported dynamic structures remain opaque. Concrete shape/dtype observations use a separate explicit isolated CPU profile. `set_dropout_probability` edits an authored float literal in Dropout `p` or MultiheadAttention `dropout`; `update_configuration` edits a unique top-level float only when every reader is a fully registered probability constructor. Derived/ambiguous values and integer probability literals remain unsupported.

The retained static RebindInput API proves conditional same-base Identity/Dropout/ReLU/GELU compatibility in an entry-root straight-line forward; it explicitly leaves G6 not_run. The new `structural-verified` path handles bounded unary and MultiheadAttention positional/keyword `Name` slots with declared named inputs. It freezes the original-source expected structural delta before lowering and compares complete staged facts plus actual CPU producer/shape/dtype/gradient/state observations. A failed/unavailable execution cannot enter ReviewReady. `replace_activation` supports exact no-argument ReLU↔GELU constructors; Studio and CLI require the same explicit profile. Inspect `supportedIntents`, `activationScope`, `structuralRebindScope` and `runtimeProfiles`. In-place effects, import-time mutation, dynamic control, aliases/reassignment, unknown dependencies and unsupported authored/shared scopes are blocked.

For optional execution, create only the formal `.venv-runtime` using the exact CPU lock and official PyTorch CPU index as documented in the checkout README. Then run the explicit authored fixture profile:

```bash
PYTHONPATH=src .venv/bin/python -m archcanvas_cli runtime \
  --root fixtures/multi_input --entry model:MultiInputAttention \
  --input-spec fixtures/multi_input/input-spec.json \
  --interpreter "$PWD/.venv-runtime/bin/python" \
  --dependency-lock "$PWD/requirements-runtime.lock" \
  --output /tmp/archcanvas-runtime-receipt.json
```

InputSpec declares all named shape/dtype/fill values, seed, modes and empty constructor. Linux x86-64 Bubblewrap namespaces/seccomp are mandatory and verified with real host file/source/network/process/resource probes. Receipts bind locked interpreter/framework/environment bytes, frozen source and input specs; per-mode observations record module calls, ports/producers, shape/dtype, forward/backward, same-seed reconstruction replay, parameters/buffers/shared objects/storage and state mutation. No checkpoint, optimizer or training progress is loaded or migrated. This is sample evidence, not numerical equivalence or general Python correctness. Isolation failure disables execution while static viewing remains available; detailed resource and portability limits are in [runtime-compatibility.md](runtime-compatibility.md).

The local service registers imported source corpora as managed working copies. Its parameter prepare action re-analyzes that registered source, verifies both source/IR bindings, prepares an isolated single-file token change, and returns the actual diff and affected calls. Approve binds the exact review digest; commit verifies an unconsumed signed approval, corpus/staging freshness and journal/backup before replacement. HTTP changes affect the managed copy, not the imported original directory. A successful managed-copy commit does not mean a user's original file was written.

The formal CLI implements `patch prepare|configuration|activation|rebind|review|approve|commit|discard`. Every action requires explicit `--root`, `--entry` and a project-private `--store`; inspect each action's actual `--help`. Prepare/configuration requires exact target/parameter/value/source digest; rebind/activation additionally requires its operation arguments, `--input-spec`, `--runtime-interpreter` and `--dependency-lock`. Later actions use `--transaction`; approve requires the human-reviewed `--review-digest`, and commit its unconsumed `--approval-id`. Profile, input, source, staged bytes or runtime-environment changes invalidate approval. CLI commit writes the explicit source root; the Python API shares these guards. A browser managed-copy action grants no approval to write the original user root.

The service exposes source-bound `structural-rebind-options`, asynchronous `structural-rebind-jobs`/`activation-jobs`, session-bound runtime job polling/cancel, and shared transaction review/approve/commit endpoints. Runtime environment paths are chosen by the formal service, not HTTP callers. Keep the actual job/transaction IDs; cancel is an execution failure and cannot authorize a source commit.

After commit, use the returned re-analysis to reconcile only uniquely matching visual identities. Visual undo is not source rollback. Review the concrete diff with the human for real model changes; test approvals in `/tmp` acceptance projects do not authorize future model edits.

## Authored model workspace

The current Studio provides a separate “搭建模型” workspace with 17 catalog modules, typed tensor DAG connections, parameters, deletion, undo/redo and draft CAS persistence. `GET /api/authoring/catalog`, `POST /api/authoring/validate`, `POST /api/authoring/generate` and `/api/authoring/drafts/{id}` are actual service APIs. Generation requires a complete supported DAG and exact static source round-trip verification; opening it registers a fresh managed copy. Declared shape/dtype deductions are not runtime observations. Existing imported source-bound CanvasDocuments retain their protected semantics; editing a draft does not synchronize previously generated copies. Attention, LSTM and composite templates are not authoring support. See `docs/m4-authoring.md` in the formal checkout.

## Bounded shared batch routing

Main scenes, detail exports and authored drafts now share a deterministic, budgeted refinement of the existing obstacle routes. Different-tensor crossing and overlap counts cannot increase; endpoints, source/target direction, identities, node layout, pins and source facts are preserved. Shared nonempty tensor identities may keep common trunks. Oversized/congested inputs may keep ordinary routes. This reduces some overlaps and bends but does not imply a crossing-free, shortest or aesthetically certified layout. Consult the configured checkout’s `docs/m4-routing-refinement.md` for the current build, measured CPU costs, actual browser/export evidence and open M4 gates. AI exploration roles are automation evidence and never real research/publication reviewers.
