# Independent authoring visual review plan

This plan is an AI review protocol, not a human participant record. The reviewer does not operate the browser or edit product code. Root performs native actions and freezes the resulting images and public DOM facts. No model execution, physical publication acceptance, performance measurement or full catalog certification is implied.

## Suggested product behavior

Make the circle, visible label and reasonable surrounding margin one predictable port hit target. Use an explicit painted transparent hit shape behind the icon/text, with distinguishable input/output captions, an obvious selected-source state, and a clear valid-target hover state. Preserve separate hit targets for merge inputs. The intended target should win when its hit area overlaps its own node body; it must not conceal node-title dragging or neighboring ports. Keyboard/button semantics can be supported, but this native protocol concerns actual pointer hits.

Use one port geometry contract for drawn circles, labels, route endpoints, connection preview and native drop targets. For explicitly vertical simple chains, bottom-output/top-input endpoints should allow straight links. Horizontal layouts should keep right-output/left-input endpoints. Mixed layouts, multiple inputs and fan-out require stable, distinguishable ports and routing lanes. Moving one neighbor should not silently attach an existing edge to another merge input. The implementation may choose its own orientation rule; the review checks observable identities and geometry.

Use a meaningful output caption, such as Output/Tensor or the declared return label, instead of a clipped generated `return:n_...` identifier. Preserve canonical identities internally and in evidence; a display change must not rewrite the authored node or tensor identity. Inspect captions and direction labels at native100% and actual Fit, including long labels and Add/Concat input names.

## Evidence required for native hit claims

For each selected port and each tested point, collect before the action: node ID, port ID/direction, port-group accessible name, group/label/circle/hit-shape `getBoundingClientRect()`, SVG viewport rect, ancestor transform, circle center transformed into screen coordinates, and the nearest port/node/edge from `elementFromPoint()` at label center, circle center, group center and a point in the intended label margin. Record whether each point is inside the viewport. These are DOM observations, not a substituted native event.

Perform native clicks/drags at the observed coordinates. Record the action's exact coordinates, mode, source and intended target, edge identities before/after, node positions before/after, camera before/after, build URL/hash, pending connection state if publicly exposed and visible notice. Use a separate screenshot call after the action, bracketed by public state snapshots. If a first attempt fails, preserve it; a successful retry is a separate attempt, never a renamed success.

Match every created edge by both endpoint IDs and port IDs. A status message or edge-count increment alone does not establish attachment to the intended input. DOM `elementFromPoint()` agreement alone does not establish pointer handling. Node selection or movement during a label click is a failure for that port-target attempt.

## Bounded native matrix

1. Reopen the literal four-node chain and explicitly position it vertically. At native100%, connect Input→Linear by label-to-label clicks, Linear→GELU by circle-to-circle clicks and GELU→Output by a circle-to-label native drag. Preserve pending-output frame and completed-chain frame. Undo/delete the relevant edge and separately test label-to-circle drag, circle-to-label clicks and group-center clicks. Repeat one label-pair case at actual Fit. Check no accidental node move and exact intended endpoint identities.
2. Click Arrange with before/after positions frozen, then inspect the resulting horizontal simple chain. Check endpoint circles touch the link endpoints, arrowheads enter the intended target, labels do not overlap the main kind/title, and adjacent connectors have no visible crossing or needless returns. Save/reopen and confirm matching authored labels, edge endpoint identities and layout positions.
3. Build a vertical simple chain with the new geometry rule. Check three visible links are straight if their x coordinates align and the free corridor is unobstructed. A zero-length SVG command is not counted as a visible bend. Inspect actual raster pixels rather than route metadata alone. Do not require straight links after deliberate horizontal offsets; those should produce bounded understandable detours.
4. In a horizontal fixture and in a two-input Add/Concat merge, test each labeled input separately. Freeze both endpoint identities, route facts and local100% screenshots. Inspect input labels, hit-target separation, no accidental connection to the other input, clear fan-out branches and arrow direction. Failure of one merge input is not hidden by success of another.
5. Insert the current MLP/CNN/residual presets in distinct native attempts. Inspect every visible edge at Fit and local100% for complete labels, meaningful caption, collisions, crossings and excessive bending. Preserve actual first drag outcome. This checks those bounded preset insertions only, not all17 modules' runtime behavior.
6. With an established chain, use Pan mode to move the view right,left,up,down, each from an identified baseline or with the reverse motion restoring it. Freeze camera and draft positions. Check camera transforms change, node positions/edge endpoint identities remain exact, visual links stay attached, captions and hit targets move together, and the same label/circle connection still works after a pan. A partially clipped Fit/local frame cannot certify offscreen routes.
7. Move a node right,left,up,down in Select mode as a distinct trial from camera panning. Check edge endpoints follow it and restoration removes temporary detours. If movement deliberately overlaps another card, inspect the warning and explicit recovery; do not claim autonomous avoidance. Undo/redo and save/reopen have separate identity/layout checks.
8. Open the newly generated managed publication view and inspect its Output subtitle and the authored display labels. A clear generated view does not override a poorly routed authoring draft. Static generation/source binding is independently audited; it does not demonstrate training or inference.

## Reporting rules

Review actual native images and any separately labeled SVG conversions. Mark images that omit endpoint pairs, show a modal or fit text too small as limited, and request a local frame for the unresolved region. Preserve all old seals, raw files, declared failures and observer corrections. Bind before/after hashes of reviewed originals. Pass/fail applies only to a named case and observed operation. Humans remain0, current performance and physical publication gates remain open, and global aesthetics are not certified by a few successful native trials.
