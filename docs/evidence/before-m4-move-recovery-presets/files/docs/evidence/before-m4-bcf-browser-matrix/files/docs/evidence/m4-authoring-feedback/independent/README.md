## UI 集成的只读证据

`source-review-followup.json` 中每项都有源码路径、行号和具体观察：排版只提交一次历史操作，适配该操作返回的新草稿；适配还包含路线点；错误通过当前草稿和注册目录按稳定节点 ID 解析并聚焦；编辑/撤销清除后端反馈；无效原始输入即时标记并阻止保存与生成；保存、重开、生成的成功与失败都有草稿快照身份保护；初始检查还有 mounted/初始快照保护，目录先于验证安装；无结果搜索诚实说明暂缺模块和清空搜索操作。

本审查发现并由主代理修复了三个额外反馈边界：Escape 原来缺少无效输入放弃提示；初始验证原来早于目录安装，导致不能定位注册字段；数组参数的引用随其他视觉编辑被克隆，原来会清除无效原始输入。最终 UI 对数组使用序列化实际值作为同步依赖，值不变的克隆不会重置原始输入，真正参数替换、Escape 和字段卸载则明确提示放弃未提交的无效输入。

`public-tests-execution.json` 的 UI SHA 是 `c87918047f47a3eaad2ceccf33790b3eff6880a6e68b2df118ea2d0370671438`。其后的数组输入连续性修正只改变 UI，最终源码审查的 UI SHA 是 `080fa734f49056305619a90b574e1fb8880c5e684fd6aa2bac3e837d390d5808`。公共测试、helper、API、搭建核心、路由和类型 SHA 均未变化，因此没有重复运行不依赖 React UI 的公共测试；两个时间点与差异明确保留。

## 证据边界

- 两项传输测试使用 mock，不是实际服务器 HTTP 回归。真实 HTTP 契约由后端代理另行验证。
- 延迟响应测试只验证旧 ID 无法绑定同名新图；没有模拟 React 状态更新竞态。组件异步保护是只读源码证据。
- 数值测试使用手写参数 metadata，不能宣称已逐项检查实际目录中的全部模块。
- 本代理没有在这一反馈阶段控制或视觉检查真实浏览器。工具栏自动适配、无效字段保留/放弃、同名错误定位等实际 UI 回归由主代理采集。
- 这些结果没有认证出版排版、箭头美观、性能或真人新手体验，不能填补 M4 真人研究席位和真人出版审看。
- 本轮未安装依赖，未执行用户模型，未调用失败原型目录，未重复完整测试或构建；正式工程完整验证由主代理完成。
