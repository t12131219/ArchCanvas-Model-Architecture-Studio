Two actual standard frontiers were captured with both frozen v16 and formal v17 runtimes. All node geometry, recursive source authority and independent wire contacts are unchanged. Each capture is tied to completed matrix and runtime hashes in the corresponding route-diff JSON.

For LayerNorm LSTM `initial` (also repeated in `all-collapse`), only `route-0036-35` and `route-0037-36` (`body → output`, distinct recorded slots) change. The complete actual routes are retained in `layernorm-lstm-v16-v17-route-diff.json`.

For multiplicative-integration LSTM `all-open` (also repeated in `all-reopen`), `route-0015-14` (`params → uz`) shortens 28px and loses two bends. `route-0016-15` (`params → alpha_wx`) and `route-0017-16` (`params → input_term`) each gain a 14px terminal-adjacent band and two bends. The total is length −28, bends +2, near-parallel runs −2 and near-parallel length −56; contacts remain unchanged. Actual routes are retained in `milstm-projection-v16-v17-route-diff.json`.

The performance isolation agent independently disabled only the new terminal-band follow-up while keeping the real-producer spine and existing budgets: both cases returned to all v16 metrics. Trace receipts found ample remaining budgets (LayerNorm initial 216 validation / 443 quality operations, MI all-open 147 / 177); the change therefore came from accepted terminal bands interfering with the subsequent original shortcut pass, rather than exhausted budgets. The product remained frozen during diagnosis. The next candidate must let the established shortcut cleanup finish before optional terminal-band work, retain the same finite budgets and avoid an increase in raw bend count, independent contacts, crossings or crowding.
