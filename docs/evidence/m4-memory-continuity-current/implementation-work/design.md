# Memory display continuity implementation design

This is a pre-implementation design, following the read-only routing research. Product source has not changed. The baseline is the current formal renderer's complete same-scene routing computation, not a prototype runtime, persisted cache or runtime fallback. The old dy14→15 behavior remains until implementation and independent verification. M4 remains partial; M5 has not started.

## Computation order

1. Build current visible nodes, original display-side projections, port groups and all route requests exactly as before. Run the complete current `route.batch()` once, retaining its final result as this scene's immutable comparison baseline.
2. Derive at most one deterministic side projection for each eligible memory edge. Both effective endpoint cards must be collapsed and have a shared nominal vertical band. Project `.55 * height` anchors through the actual Repeat front/backplate union. Source right and target left must leave two six-unit leads after two-decimal coordinate rounding. Use gap midpoint H-V-H, or a straight horizontal segment at equal y. Expanded endpoints, overlap, tiny or nonfinite geometry are retained.
3. Validate the proposed route against that final fixed complete batch, then against any previously adopted memory routes in the same deterministic projected-edge order. Non-memory paths are never rerouted. Every positive proposal decision requires complete geometric checks; unknown or exhausted work budget retains the baseline. No warning permits an unsafe proposal. There is no later batch/family/residual optimization.
4. Update each accepted route and its derived displayed ports together. Rebuild only canonical coverage of memory display ports from actual chosen projected consumers. Preserve all original coordinates and coverage of every retained non-memory or memory consumer. Recompute captions/guides/scene bounds normally from the chosen route list.

## Protection requirements

Inclusive intersection checks count joints, endpoint contact and collinear span unions, including peers with the same tensor or owners. Proposal contacts/spans must be a subset of baseline occupied geometry; the chosen-peer comparison also prevents separately safe proposals from conflicting with each other. Reject self reversals and nonadjacent self contacts. Reject a route whose centerline length increases; dy14's extra necessary bend is permitted to repair the left-port arrival normal. Every first/last segment must follow its new outward port normal and preserve six-unit leads.

Measure nominal visible peer stroke separation at combined half widths. With finite known positive widths, a proposal cannot contact another peer's nominal stroke; neither equal tensor names nor equal appearance allow a new shared trunk. All nodes' nominal front/backplates are obstacles. Unrelated expanded frames and shared-ancestor headers are protected. Own first/last lead segments may leave/meet their actual exposed boundary; all middle segments must stay outside padded own geometry. Padded unrelated/header clearance includes the proposed nominal half width. Arrowheads and resolved font pixels remain outside this geometry claim.

Use bounded integer counters for node/route/point/pair/segment/obstacle work. Do not evaluate partial metric results as clear. The fixed complete batch must remain byte exact whenever the proposal is ineligible, rejected or unknown.

## Display port bookkeeping

Canonical identity is separate from displayed side identity. The current displayed port keys encode binding, role and side. Maintain a chosen side for each projected edge rather than globally changing a canonical binding's side. For each endpoint, derive side groups from the complete chosen edge list, collect canonical edge IDs in original architecture order, and compute canonical bindings from those IDs. Existing side ports with retained consumers keep their exact geometry and nonempty original coverage. Accepted consumers are removed from their old side's coverage and assigned to the new side's coverage. Delete an old display port only if no projected consumer retains it. A new side may share the public port for the same exact canonical binding and role, but never merges the represented tensor edges or fabricates a trunk. Non-memory port arrays/positions/coverage stay byte exact; test mixed memory consumers and dashed/style splits explicitly.

## Historical oracle compatibility

The old `normalizeDefaultMemoryLabels` adapter rejects all geometry changes. Do not weaken it into an automatic path whitelist or edit historical gold. A version adaptation must first establish the full current scene against a hash-bound immediately prior scene generated from the same actual document. It must reject every non-memory path or port change and every canonical fact/style/identity change. For an adopted memory edge, independently derive eligibility, required right/left ports and midpoint path; check exact chosen geometry and unchanged remaining port consumers. Then restore only that bounded known presentation change when comparing an older oracle. All explicit/custom caption rules and negative controls remain. The separate independent auditor is responsible for reviewing exact protections rather than using this adapter as proof of route safety.

## Evidence to produce

Generate current source-backed Transformer matrices for all caption modes, paper/mono,85/180mm,whole/detail; source and target y sweeps at both signed thresholds and adjacent fractions; Repeat-aware x gaps around12 units and exposed/front-card zero gaps. Rebuild all nine current source-backed frontiers, including expanded Encoder/Decoder, Repeat, opaque/shared and multiple memory consumers. Literal counterexamples cover gap bodies/headers, joint-only peers, close nominal strokes, same-tensor crossings, distinct canonical bindings sharing names, style splits, invalid widths and budget exhaustion. Compare complete non-memory geometry and canonical inventories to the frozen baseline; input CanvasDocument/layout/history remain immutable. Verify deterministic preview/commit/undo/redo and persisted/exported scenes. Native CUA gestures and settled raster/public-DOM evidence remain required; static geometry cannot claim first-paint, physical publication, global aesthetics, performance or human-task acceptance.

The previous finite research found312 eligible and192 retained of504 frozen rows. Those are proposal results, not required implementation pass totals. The new implementation may retain more scenes when stricter or previously untested guards apply; any reduced scope must be explained and cannot silently replace the dy14→15 continuity target. Horizontal six-unit gap transition, expanded-memory routing and font/arrowhead geometry remain separate limitations.
