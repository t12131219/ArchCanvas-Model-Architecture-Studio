# Caption-guide publication integration repair

The actual Studio whole-SVG export failed because its generated path.data-caption-guide-id attribute was outside the publication allowlist. The formal CLI using a fresh default Transformer scene independently reproduced the same failure (exit 2, zero output bytes). The nine existing publication tests did not exercise a real caption guide. Two new tests cover actual source analysis → formal TypeScript scene → publication conversion, plus literal allowed and disallowed decoration contracts. With the old exporter, the expanded suite reports 11 tests and seven errors; the final exporter passes 11/11, with no skips. The first isolated test invocation omitted the formal src path and failed import; that distinct invocation failure remains preserved.

The allowlist admits only the exact path attributes data-caption-guide-id, data-caption-for-edge and pointer-events=none. An identified guide must carry both valid local identities, have a unique decoration ID distinct from ordinary SVG/tensor IDs, reference a rendered tensor edge, and remain an inert, unfilled, unarrowed path outside marker definitions. Unknown attributes, external URLs, events, CSS and invalid marker/guide identities stay rejected. The change does not strip guide geometry or presentationDecorations metadata.

Six actual converter artifacts (SVG/PDF/PNG, at 85/180 mm) are retained with receipts. Both exported SVGs preserve the actual guide attributes and exact sourceFacts, canonical renderedBindings and presentationDecorations. PDF page boxes and PNG dimensions/density are independently checked by the integration tests; this is not physical readability or font-embedding approval. Browser success after retry is separate evidence. No model code was executed, no Studio source or dist was edited, and no frozen package was rewritten.
