# Browser memory-caption policy investigation

The real encoder +24-y drag removed the visible memory caption and guide, while edge:44 remained a memory tensor binding with exact source/target/canonical IDs. Undo restored the text and guide. Detached reconstruction reproduces the actual moved path exactly. The sourceFacts, sourceDigest and irDigest also remain exact across these browser captures.

The cause is the existing scene.ts default caption rule: an unlabeled memory role receives the word memory only when the projected source/target y difference is strictly less than 15. The default is computed before placeEdgeLabels; the helper skips empty labels and cannot diagnose the absence. The same condition already exists in the frozen before-change baseline. Independently replaying vertical ±14, ±15, ±16, ±24 and horizontal ±24 shows the caption disappears at |dy| ≥ 15 in baseline and current scenes and their root details. This is an existing presentation stability gap exposed by native gestures, not deletion by the new placement helper and not semantic corruption.

A precise future presentation fix is e.label ?? (e.role === 'memory' ? 'memory' : ''). This retains explicit labels (including explicit empty strings) and lets the bounded placement helper associate the caption or give a diagnostic. A detached counterfactual with an explicit memory label shows the same moved route can carry memory at (288,489.5) with no guide or diagnostic. That experiment modifies a copied static IR only; it is not the proposed production mechanism and was not saved. The display-port side rule switches at the same threshold; it requires a separate general design review. Keeping a caption does not itself prove stable ports or globally attractive routes.

No product, dist, service, source file, saved canvas or frozen research package was changed by this investigation. Treat the four-direction stability/readable caption gate as unproved until a separate failing-before/fixed-after stage checks threshold boundaries, gestures, undo/save/reopen and whole/detail exports. The strict publication integration repair is recorded separately in export-integration-repair.
