# Current performance collection contract

Read-only audit of 24 finite, archived inputs. No product, browser, service, source model or system setting was operated. The frozen initial DenseStress300 envelope is Canvas revision 5/storage 1, with root and `call:instance:model.DenseStress300.network` expanded and **no pins**. Its canonical architecture has 304 nodes/304 edges and 300 leaf children of the network. This is an initial seed fact, not a claim about later live browser state. The root Agent operates the native browser independently.

## What the two visible buttons actually do

Both are shown only when the URL has `benchmark=1`. They inspect and operate the **currently opened document**, not a synthesized benchmark fixture.

| Control | Actual behavior | Relevant receipt |
|---|---|---|
| 运行 20 组性能采样 | Finds the first enabled, collapsed, depth>0 tree container; two-second idle baseline; synthetic `button.click()` warmup expand/collapse; 20 measured expand/collapse pairs; final fit. Typed operations change the current document revision/history. Starting frontier is restored; camera is fitted. | `性能采样 JSON`; `measurement.latency=two-animation-frame-paint-proxy`, `syntheticScenarioEvents=true`; 40 recorded trials. |
| 开始原生输入采样 / 结束原生输入采样 | Observes ordinary tree `.tree-toggle` **click** or canvas `[data-expand-id]` **pointerdown** in capture phase. At most 100 trials. Reads current source-bound SVG, geometry and unrelated pins, then after two rAF reads it again. Does not dispatch operations. | `原生性能 JSON`; `protocol=archcanvas-native-performance/1`; `trials`, `snapshot.eventTiming`, `summary`, `frames`. |

The frozen Dense seed has no collapsed non-root container. The synthetic button therefore rejects until the network is ordinarily collapsed. The native button can begin with the expanded seed and record network collapse→expand. Property-panel “原位展开/收起” is not captured by this native observer; the supported tree/canvas handles are required. A hand-tool pointerdown over an expand handle is captured by the observer even though the product gives pan priority: it can produce an invalid toggle trial. Use the selection tool for toggle collection and preserve such failed attempts.

Native latency matching requires a trusted event, same event name and canonical target, positive `interactionId`, timestamp difference≤8ms, nonnegative ordered processing times, and a **unique candidate on both sides**. Missing, ambiguous, under-threshold or unformed entries remain null. Native Event Timing is reported at a minimum 16ms threshold and 8ms duration quantization. `summary.nativeInputToNextPaintP95Ms` is the valid matched toggle subset, not all inputs or page INP. Native matching does not deduplicate several trial events by interactionId; distinct delivered interaction IDs should also be reported.

## Immediately executable bounded native sequence

1. Fix and record the build/source/IR/document, actual canvas viewport rect, camera, DPR, UA, current host visibility/focus, publication preset and font/hardware facts. Confirm the exact 300 leaf bodies are geometrically in the viewport, and inspect actual legible text and panel occlusion. 304 DOM nodes alone is insufficient.
2. With selection tool, select `input:model.DenseStress300:features` and use “固定 / 解锁” or “固定位置”; verify `.publication-scene[data-pinned-ids]` contains that canonical ID and its body is actually visible. This input is unrelated to the network subtree and remains visible on collapse. The initial seed has no measured pin evidence.
3. Start native sampling; use one ordinary tree/canvas network toggle at a time, waiting for settled geometry between operations. Record collapse→expand→collapse→expand, or a predeclared longer sequence, without fit/focus/zoom/resize or other edits in the window. The network target is `call:instance:model.DenseStress300.network`. On a fresh saved5 seed with only one pin operation, this sequence would be revision6→7→8→9→10; actual live revisions must be read rather than assumed.
4. After the last operation, wait for its post-operation geometry and separately allow a predeclared Event Timing delivery interval before Stop. Preserve original timing and wait facts. This mitigates, but does not cure, the synchronous stop protocol's missing unformed/undelivered entry risk.
5. Read the full `textarea[aria-label="原生性能 JSON"]` and preserve every attempt. Run `node scripts/validate_native_performance.mjs <raw.json>`; independently inspect exact target/revision/frontier restoration, pins and geometric viewport coverage. A validator exit0 is internal receipt consistency only.

Required geometry relations for each valid toggle: same document/source/IR, after revision=before+1, correct expanded membership and larger/smaller frontier; target body anchor displacement in **screen CSS pixels ≤8**; unrelated pin displacement in **canvas units exactly 0**, with nonempty measured pins and no unmeasured pins. Screenshot/DOM/document comparisons must additionally show the prior 300 leaf arrangement returns after re-expansion. The native protocol only records top-left body anchors; it does not prove full local layout restoration or viewport coverage.

## Explicit gates and missing measurement scope

| Requirement | Present evidence needed | Existing control limitation |
|---|---|---|
| 300 visible objects input-to-paint p95≤50ms | Predeclared workload/object definition;≥300 actual readable viewport objects; every attempted input and missing outcome retained; actual response paint joined to the input, fixed environment. | Native observer only logs toggles; it omits raw click down/up sequence, pointermove, wheel, keys and overflow totals. | Interaction target≥50FPS | Same Studio surface presentation feedback/frame sequence over the actual active interaction interval. | `frames.fps` is `(N−1)×1000/(last rAF−first rAF)` over the whole session including waits. Paint, rAF, composite submission, screenshots and DOM changes are not actual presented FPS. |
| Medium-subgraph incremental p95<500ms | Frozen explicit medium workload/size, repeated actual browser expansion with independent incremental timing and geometry. | Dense network has 300 children: it is a large stress workload, not a certified medium one. | Anchor≤8px, unrelated pins0; restored local layout | Actual measured nonempty unrelated pins/anchors, exact layout restoration on repeated expand. | Protocol does not validate visibility/occlusion/readability, complete layout or pin-set completeness. Empty pins must stay unmeasured. |
| Fixed hardware/fonts and repeated conditions | Actual browser/hardware/power/font bytes, same workload/viewport/DPR; predeclared distinct condition pair, alternating A/B with≥3 runs each, every failed/no-input attempt preserved. | UA/font-loading state is not font byte/hardware lock; historic false/false visibility requests did not establish A/B. No field or validator imposes this matrix. |

The≥3/A/B repeated-condition protocol comes from the frozen current condition-review and Skill references; the formal plan states fixed environment and targets, but does not prescribe a numeric medium node range, continuous gesture sample count, or A/B pair labels. Those should be declared before collection, not chosen after seeing timings. A smaller medium workload is necessary alongside Dense300, not a replacement for it.

Current callable presentation capability remains **unproved**. The archived capability audit found no declared tracing/CDP tool and native UI control disabled; it did not obtain presentation feedback. This read-only design audit does not recheck live tool inventory or operate a trace. No reported rAF value closes that gate.

## Independent input observer alternative

`scripts/m4_input_observer.mjs` protocol2 records trusted pointerdown/move/up/cancel/lostcapture, click, keydown/up, wheel and window blur; coalesced pointer data; full public SVG binding at trial boundaries; explicit buffer drops and observer-cost categories. `validate_input_observation.mjs` separately checks pan/drag endpoints, raw input eligibility, symmetric unique timing joins and deduplicates matched discrete durations by interactionId maximum. Continuous pointermove/wheel remains **first observed DOM geometry proxy, not paint**. It never substitutes null timing with zero.

The existing `/__m4/` harness exposes “开始会话”, “准备此操作”, “结束此操作”, “结束会话并显示收据”; operation values `drag`, `pan`, `zoom`, `undo`, `redo`, `toggle`, `pin`, plus target/anchor IDs. It runs an explicitly fixed **1280×720 iframe**. Using it unchanged would replace the current large viewport and invalidate the Dense300 legibility environment. It also has synchronous queued-record drain rather than a guaranteed asynchronous delivery window. Therefore it can support a separate bounded input diagnostic; it cannot silently provide same-condition complete continuous/presented certification for the current 42939 workload.

Readback fields to preserve: native `bindingAtStart`, every `trials[].before/after`, `eventAt/capturedAt/trusted/eventName/targetId/operation/error`, `bindingValid/targetChanged`, full Event Timing entry, target screen-anchor delta, every `pins[]` with measured status and both coordinate-space deltas; `snapshot.supported/visibility/longTasks/eventTiming/interactions`, raw `frames.intervals`, first/last frame times and buffer flag; the environment and actual SVG/body viewport snapshots outside the native summary. Complete all-input/stop/observer-overhead/presentation denominators require stronger instrumentation; they are not already implemented by this panel.

The native receipt validator allows empty, failed or missing-match trials when internally consistent. The synthetic validator requires at least20pairs/40finite proxy trials; both allow slow timings and neither applies numeric acceptance thresholds, enforces300readable objects, fixed environment, pins, medium size, repeated A/B, or presentation evidence. Run them as consistency checks and separately report each gate outcome.
