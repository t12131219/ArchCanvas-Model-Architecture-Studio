# Summary 三份大图、取消与 Studio 历史接入

日期：2026-10-28。整体移植仍在进行；本报告只记录本阶段实际变更与验证，不替代两份主迁移文档的完整验收。

## 迁移范围与面板衔接

继续以 Summary 的完整 IR、原生图元、前沿投影、物理端口、路由校验和组装模型替换重叠功能。Studio 保留顶部模型菜单、视图/编辑切换、左侧层级、右侧对象/图例/页面、折叠功能面板、状态栏和导入/导出入口。

| 用户入口 | 实际行为与状态流 |
| --- | --- |
| 模型 → Summary 模型库；右侧折叠区 | 读取已核对字节、SHA256、身份和计数的完整原始 IR，交给 Summary 文档 reader 和 Worker。43 个模型均进入同一路径，不抽样、裁剪或替换成小图。 |
| F0/F1、层级定位、语义切面 | 原版 Summary 决定可见图元、精确归属账本及路线；未完成或失败路线仍明确标记，面板提供继续布线，不将草稿当作合法路线。 |
| 状态栏“取消当前图操作”；Escape | 仅在实际 Worker 请求待返回时出现/生效。终止该代 Worker，原请求收到明确取消结果，不触发基础设施失败的主线程重算；下一次操作新建 Worker 并发送完整来源。 |
| 初次恢复的加载层 | 显示读取文档/校验视图进度，Worker 运行时提供“取消恢复操作”。取消命令可在启动 promise 未完成时到达，避免排在自身等待的 Worker 后面。 |
| 优化连线 | 验证完成后才记录历史、替换图并保存。失败或取消不会新增空撤销项、清空 redo 或替换原图。兼容拖动的既有 gesture receipt 负责恢复松开前的状态。 |
| 图元别名、颜色、页面、图例与说明 | Studio 发 visual 命令；原生共享语义快照保存前后状态，几何和展示叠层独立。连续视觉编辑不再为每个历史项复制完整 IR。 |
| 保存、刷新、文件导入/导出 | 沿用 Summary IndexedDB 与原始完整编辑 JSON。宿主保留保存标记。启动不再为每个非当前保存文档预先执行路由，只在实际打开时建图和验证。 |
| 编辑 → 视图 | 从完整 IR 创建 Summary 声明编辑副本；编辑和当前组装图仍在唯一原生 runtime 中。返回视图保留当前组装稿，Python 写回继续走显式正式事务。 |

## 实际自省及修复

1. 正常 8 秒路由预算的诊断证明三大图 F0 都能通过完整路由校验。最大 Transformer F1 初次出现 18 条 pending、2 条失败，继续两次后全部通过。此前 300 ms 诊断不能代表正常产品行为，原始 JSONL 保留在本阶段 evidence。
2. 取消和 Worker 故障必须区别处理。错误、反序列化失败和缓存失效仍使用完整输入独立验证 fallback；用户明确取消返回专用结果，在 app 层抛出 AbortError，不能 fallback。
3. 30 步浏览器视觉编辑暴露 `studioVisual` 仍用两次 `E.clone(graph)` 深拷贝语义。改为两份原生 `N.snapshot`，增加执行实际处理函数的 30 次编辑回归，检查同一 IR、独立几何、逐项叠层和不可变事实。浏览器 RSS 仍较高，不能用引用数量的改善声称整个浏览器内存问题已解决。
4. 首次大图刷新越过原有 30 秒握手期限，宿主回落到默认模型并错误显示未保存。加载等待改为有明确 120 秒总上限，提供启动进度/取消，并将非当前文档建图延后。实际打开仍执行完整原生校验；不通过延长超时掩盖取消缺失。
5. 进一步逐字节复核发现，恢复时调用 `N.decorate(graph, null)` 会把已保存 `semanticRevision` 重新设为 1。现在保留合法的已存版本，只有真正的新语义转换才递增；新增反例要求恢复前后的完整 graph JSON 字节一致。
6. 大图截图暴露右侧四位数统计沿用 25 px 列宽而重叠，列宽改为按内容分配，保留 Studio 面板结构。
7. 开发过程的失败日志、第一轮浏览器截图和修复前 RSS 样本保留；最终验证范围与生产字节另行核对，不把早期成功项拼成最终整体验收。
