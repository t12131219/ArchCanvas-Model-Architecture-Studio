# 陌生模型的通用编辑与预览修复（2026-10-16）

本次针对 `act` 复查中发现的三个阻断，补通有限的结构编辑生成、自定义模块检查协议，以及源码修改到递归预览的显示与定位。实现位于正式项目和源码树 Skill；已安装的 beta.12 没有随本次修改重新发布或安装。

## 行为变化

| 原问题 | 当前行为 |
| --- | --- |
| 源码模型加入并连接模块后，一律拒绝生成 | 对明确的源码调用参数或静态返回槽，支持一元模块链插入、自定义源码模块插入、一元调用旁路删除、删除后插入替换，以及可证明支配关系的已有局部值重接；生成独立副本后重新分析 |
| 源码模型含自定义模块时，检查响应报格式错误 | 原模型的源码保留合同优先，前后端一致读取 `source-preserved-graph; no model execution`，分别报告连接完整性和生成资格 |
| 直接修改源码后，新模块被不透明区域遮蔽或无法选择 | 缩小构造器未知区域的影响范围；补充独立重建的真实调用位置；按源码依赖、祖先和后代分配检查区域，公平使用显示预算 |
| 新源码结构生成后，被旧折叠状态阻止打开 | 验证所有新模块的源码实例，展开其必要父级；当源码层级改变时重新排布新图，保留原草稿 |
| 新图保存后返回编辑，再次生成被隐藏结构缓存阻断 | 有结构修改的原草稿保留原编辑层级、拓扑、坐标和缓存；新图只回传有准确绑定的名称、颜色及端口设置，避免新源码的自动展开改变旧源码编辑锚点 |
| 同一构造器在两个分支中被混为一个对象 | 使用准确的分支条件和源码范围区分实例；明确冲突时拒绝绑定，重复映射不能获得唯一几何权限 |
| 展开后条件关联缺失 | 在已有张量线占用分支顶部中心时，尝试其他顶部入口与容器侧边通道；候选必须通过原有容器、障碍物和线段重叠检查 |

`src/archcanvas_authoring/source_surgery.py` 只修改独立证明的 AST 表达式和构造位置。原有条件、循环、辅助函数和未编辑语句保持源码文本；未知区域不会由视觉箭头重建。无关分支、未消费的新模块、跨作用域重接、可能被原位操作改变的局部值、反射或覆盖导致的不确定绑定均有拒绝检查。

预览仍使用迁入的 Summary_Merge 图、展开和路由技术。源码结构卡片和条件关联仍标明“执行路径未选择”，不授予张量操作生成权限。

## 支持边界

本次打通的是**可定位源码位置的有限结构修改**，不能据此验收“任意陌生模型、任意连接变化都能正确生成”。连接检查通过后，仍需查看 `generation.supported` 与具体限制；生成阶段还会独立校验，可能拒绝预检未能证明的改动。

外部 backbone、动态配置和部分控制流仍有未知内容。DETRVAE 直接修改的三个阶段仍各报告 3 个不透明边界和 3 个截断检查区域。源码结构箭头表达源码关系；shape、dtype、实际分支与数值行为未验证。写回用户原始工程继续使用单独的源码审查与提交事务。

适配标准的自动源码检查修订为 `source-inspection/3`，补入真实 `callSites` 证据并独立重建校验。旧修订不会静默复用，需要重新生成和校验。规范见 [适配模块生成标准](adapter-generation-standard.md)。
