# Summary 跨切面完整来源共享与自动保存快照

日期：2026-10-28。继 [实际 Worker 通道接入](summary-worker-transport-integration-20261028.md)之后，继续减少跨切面历史中的重复完整 IR。Summary 仍是视图、原生模型和语义的唯一实现；Studio 的面板、正式源码与事务边界保留。

## 发现与实现

Summary 原版 `G.build` 先验证并防御性复制 IR。这个规则继续保留；但每次语义切面变化后，返回主线程的新完整 core 会带另一份内容相同的 IR，使历史快照只能在同切面共享事实。

新增 `studio-shared-source.js` 在主线程和 Worker 的各自通道边界保留最多四份冻结来源。候选必须 schema、声明 digest 一致，再递归比较**完整对象内容**：所有字段、数组顺序、属性是否存在、源码证据、CPU 事件和未知扩展字段都参与比较。digest 只缩小候选范围，绝不单独作为等价或认证依据。匹配后复用同一个完整不可变 IR；任何字段变化保留独立对象。淘汰只释放池的强引用，不改变历史中仍被使用的旧事实。

接收端在原版 `G.transport.unpack` 安装 core 之前替换已完全比较相等的 IR；发送端在原版 pack 之前共享。因此原版 last/core 的精确引用比较仍一致，同切面 shell 优化不会因来源共享而失效。每代 Worker 单独建池；重建不继承旧通道的缓存身份。

认证结果、切面 state、节点语义、边 binding 和几何不会跨切面合并。来源对象相等不等于当前切面或路径已经验证；原有 validator、完整 canonical accounting 和正式事务规则继续执行。32 个原版 native 模块保持逐字节一致。

## Studio 面板、历史与保存

菜单、F0/F1、语义切面折叠区、层级树以及对象/图例/页面面板继续操作同一个 child graph。没有新增用户设置项或第二份语义实现。

30 次真实 Worker 语义切面切换后，主线程历史共用一份完整 IR，同时有 30 份不同的 state 和节点几何数组。逐个恢复历史仍验证各自切面、节点和边；更改一份额外几何副本不影响任何历史。伪造相同 digest 下的标签、目标槽位、source_evidence、数组顺序或 CPU source_stack 都不能进入旧来源对象。

`flushPersist` 的浏览器自动保存从 `E.clone(graph)` 改为原有 `N.snapshot(graph)`：冻结完整语义继续共享，位置、路径、样式、草稿和布局独立复制。浏览器 IndexedDB 最终仍 structured clone 完整数据；没有写入跨会话引用 token、语义摘要替身或丢失完整 IR。保存版本仍为 5，历史的刷新合同保持不变。

显式保存、便携编辑 JSON 和 host panel snapshot 仍存在完整序列化/重复副本；本阶段不宣称这些路径已经整体优化，也不把逻辑对象共享当作磁盘压缩或 RSS 压力合格。

## 验证与自省

新增测试检查真实线程的 30 次跨切面和逆序恢复、同 digest 修改反例、完整归档 CPU/未知字段、四来源淘汰、双向缓存引用一致，以及实际 `flushPersist` 在 IndexedDB 接收前的几何隔离。与原传输、状态精简、自适应专项一起执行。

Chromium 使用真实 Studio、Worker 和 IndexedDB 检查故障恢复、切面/历史、实际共享适配器返回引用、编辑 JSON、保存和刷新；同时复核原生手势、F0/F1、物理端口、证据模式、组装及自适应。没有从这些样例运行推导新 CPU 执行认证。

开发中两次测试假设被纠正：实际 autosave 片段需要 original 基线，测试环境最初遗漏该变量；浏览器切面请求已只发送 shell，最初从发包统计 IR 引用得到空集合，现直接记录共享适配器实际返回的引用。产品代码没有为这些测试加入专用入口；失败日志另存，本阶段最终结果只统计修正后的执行。
