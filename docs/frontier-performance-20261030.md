# 展开与折叠性能修复（2026-10-30）

本次优化覆盖所有使用原生语义视图的模型，没有按模型名称或测试项目分支。
渲染协议继续使用 `native-semantic/25`，无需仅为性能变化废弃已有布局。

## 原因与修复

1. 返回已访问的层级时，旧布局虽被恢复，但恢复前仍重新投影完整 IR、
   构建视图和安排节点。现在按完整源码内容与完整状态复用私有视图模板，
   每次复制可变几何、布局历史及作者数据。缓存最多 3 个模板、合计 8000
   个可见节点；超出时淘汰，不能由导入文档或其声明的摘要注入模板。
2. 局部原子层与普通语义层混合时，切换其他模块也会重新计算完整源码投影。
   现在仅对本运行时递归冻结的源码按引擎与实际状态复用分析，每个源码/引擎
   最多保留 6 个分析结果，并用 WeakMap 允许源码回收。多选原子展开共享一次
   完整源码投影；带独立折叠状态的范围仍使用自己的状态。
3. 原子范围成员校验与可见祖先查询反复线性查找或重建索引，改为复用 Set/Map。

没有跳过源语义、端口或连线校验。相同内容的新源码对象仍有独立的 Worker
传输核心，避免缓存复用改变来源身份或掩盖核心过期。保存的布局仍按原流程
恢复与验证；新状态的投影、布线成本仍然存在。

## 测量

同机静态基准：`node scripts/benchmark_frontier.mjs <输出 JSON>`，不运行模型
Python。Transformer 第二、三轮往返的 4 次平均耗时从 **1122.5 ms 降到
118.5 ms**（约降低 89%）；MLP 重复切换约 2 ms。计时包含语义准备和校验，
不包含浏览器传输与绘制。首次访问新状态不能使用完整模板缓存。

8798 浏览器保留用户当前 Transformer 混合视图（3371 个原始语义节点，
82/72 个可见节点），通过真实展开按钮验证：

| 操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 重载后首次折叠 attention | 2246 ms | 1452 ms |
| 恢复展开 | 2211 ms | 347 ms |
| 随后两轮折叠/展开 | 未单独记录 | 223–272 ms |

浏览器数据为应用 `data-frontier-ms`，包含 Worker 往返，到最终 render 调用前
结束，不等于屏幕呈现的完整延迟；重复切换 Worker 内部耗时为 87–104 ms。
6 次操作的源码与布局校验均为 true，全部显示连线通过几何校验；最终恢复
82 节点展开状态。截图与每次操作记录见证据目录。

静态基准的初始 Transformer 布局及恢复该布局时仍有 33 条既有待布线连接，
优化前后相同。基准的接受条件允许明确标记的待布线状态，不能据此宣称所有
图面路线都完整。上述浏览器当前保存布局的 6 次操作没有无效连线。

## 验证与边界

- 132 项相关回归全部通过，包括 43 个模型配置的原始展示对比、
  43×3 个视图的依赖保留检查、混合层级、布局、实际 Worker 往返、
  核心淘汰、伪造来源/绑定拒绝、撤销、取消及相机状态保留。
- 新增缓存测试通过：重复状态不再投影/布局，可变几何互不污染；改变实际
  源码仍重算；多选范围只编译一次完整源码，另一个范围复用分析且状态独立。
- 生产构建、预览 authority audit 及集成清单校验记录于证据目录。
- 本次没有执行 TFB 或模型 Python；不能将缓存命中性能推广为首次导入、
  全原子大图首次布线或所有设备上的延迟保证。

证据：`docs/evidence/frontier-performance-20261030/` 中 `before.json`、
`after.json`、`browser-after.json`、`browser-after.png`、`final-tests.log`、
`cache-tests.log`、`transport-tests.log`、`build.log` 与 `audit.json`。
