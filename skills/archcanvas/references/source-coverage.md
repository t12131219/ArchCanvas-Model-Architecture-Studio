# Source coverage and unfamiliar models

Use the same source-driven workflow for every model name. The preset catalog is a construction palette, not an import allowlist. A model never needs to be called Transformer, Encoder, Decoder, PatchTST or a preset name to be displayed or edited.

Parse source without importing or executing it. Identify the actual local Module entry and source root; retain source spans, constructor literals, instance sharing, ports and source/IR digests. Direct authored helper methods, module-valued constructor arguments and local module variables can be recovered. Bounded return-expression factories using ModuleList, Sequential and exact copy.deepcopy contracts can preserve independent copies. A narrowly verified standard parameter-initialization helper preserves topology. Decorated/replaced helpers, side effects, unsupported inheritance, dynamic loops/conditions, ambiguous shapes and unresolved external calls do not acquire guessed semantics.

Display an unresolved region as a source-backed opaque object. Keep its source expression and input dependencies visible. An opaque object can be renamed for display, styled, moved, connected through movable visual ports, saved, reopened, undone and exported without lowering it to a registered preset or regenerating Python. Recursively expand proven composites in the independent editing frontier; preserve hidden node edits and return to the compact source view through the original CanvasDocument history. A presentation change must not create a new managed model or silently discard a structural change.

For a config-driven branch with missing values, show the conditional boundary first and allow expansion into both authored paths. Source inspection follows local module constructors, guarded initializer assignments, attribute aliases and symbolic ModuleList element templates. A missing repeat count does not hide the available element definition. These nodes carry `sourceStructure: true`, source spans and expressions; they have no tensor ports, runtime instance identities or inferred repetitions. Keep their English source names. The original conditional boundary retains its conservative input/output bindings. Inspection is bounded to 480 added nodes and 12 levels within the total 1200-node limit; prioritize branch/module structure over expression leaves and expose truncation in metadata and diagnostics. This is available source structure, not a claim that both paths execute.

Source inspection includes separately recorded `sourceRelations` for syntactic value dependencies: nested call arguments, local assignment/alias passing, branch joins and the registered Sequential contract. Draw these as arrowed dotted source dependencies in both view and editor, with an execution-path-unresolved legend. Never chain adjacent statements, mutually exclusive branches or ModuleList members merely by their display/construction order. Local call interfaces bind positional/keyword parameters and structured returns to source dependencies, including nested composites, helper methods and Sequential. Boundary dependencies join proven external producers/consumers to the inspected entry/exit cards; their evidence names the original conditional boundaries and conservative edge IDs, without creating tensor IDs or ports. Distinct tuple/dictionary slots and variable assignments retain distinct dependencies. These relations do not establish runtime topology or shapes. Project arrows through collapsed containers and restore exact canonical evidence on expansion; movement reroutes display anchors without changing source facts. When an expanded boundary has complete visible source coverage, show the continuous source arrows in place of its redundant container strokes while retaining all original bindings in scene/draft data and export metadata. Incomplete recovery, missing children or truncation retain conservative boundary strokes. Collapsing the boundary restores those strokes. Detail exports include only source relations inside the selected subtree. Analysis retains at most 1440 source relations and reports truncation.

Ask for configuration only when selecting the real branch, verifying shapes or preparing a semantic edit depends on it. Do not infer configs, tensor dimensions, optional-mask behavior or training mode from the model name. Existing saved canvases bind immutable analysis facts; a new parser cannot retroactively add children to an old IR. Analyze into a fresh document and preserve the old document/history rather than silently replacing its facts. Additional source lowering requires positive and negative fixtures, stable identity/sharing checks, no-execution evidence and an import→edit→view→save→reopen→export check using names absent from the preset catalog.

Parameters, node insertion/removal and tensor rewiring are semantic changes. Use supported reviewed source intents or a separately validated generated draft. Source inspection nodes are not registered construction presets and cannot be lowered through the graph generator. If an opaque operator lacks a generation contract, preserve the original source and edited canvas, identify the exact unsupported expression, and retain structural work as a proposal. Successful visual editing does not establish arbitrary Python roundtrip generation or execution.

## Bounded source-preserving generation

Read live `capabilities.modelAuthoring.sourcePreservingGeneration` before using this workflow; source-tree and installed runtimes have independent capabilities. For each edited source draft, inspect `generation.supported`, `generation.topology` and `generation.limitations` from validation. `mode: source-preserved-copy` with `topology: preserved` covers unchanged source and supported explicit constructor-literal edits. `topology: anchored-edits` identifies a proposed structural rewrite; only `supported: true` passes its preflight. Generation independently reanalyzes the bound source corpus again and can still refuse the edit. A passing connection check alone does not establish generation support.

Supported structural edits have exact AST expression anchors: an existing registered unary call argument or a statically identified return slot. Insert a chain of one-input/one-output catalog modules, or a checked custom source module with the same boundary, into that expression. Each inserted module has one consumer. Custom module source and its deterministic output adapter are copied into the new corpus. Its output shape remains unknown. New constructors require verified ownership in a plain direct `nn.Module` subclass with an ordinary initializer; ambiguous inheritance, instance hooks and initialization are rejected.

Delete a proven unary module by bypassing its exact call and reconnecting its original producer. Its constructor is removed only when it is uniquely identified and unused; reflection or an escaped instance may require retaining construction. Replacement combines this bypass with an inserted chain. Rewiring uses a method input or a preceding direct local assignment in the same method, retaining its value without reexecuting the producer. Intervening calls, mutations, unresolved control flow, aliases, rebinding and cross-method values are rejected. Shared source occurrences, collapsed inputs combining several slots, shared inserted consumers and overlapping edits also require a more specific contract.

An output boundary may cover multiple authored return paths. Rewrite the selected static tuple/list/dictionary slot in every matching return separately, retaining branch conditions, the other return slots and the remaining source bytes. The new module has one constructor shared by these mutually exclusive source occurrences. Generation records all recovered occurrences; a call remaining inside an unresolved branch has a source-inspection binding, not a verified tensor-operation binding. Editing syntax-dependency arrows or inspection definitions cannot create tensor semantics or bypass these anchor checks.

In Studio, “模型 → 预览生成源码” shows the independently checked result before “创建新工作副本并打开论文图”. Switching to “视图” after a semantic draft change also generates a new managed copy; pure presentation changes may reuse the original view. The original source corpus and canvas remain available. Agent edits to a permitted source copy can instead be freshly analyzed and opened; confirm the changed module's actual source/IR binding in the new view. Neither path proves arbitrary structural roundtrip, actual runtime branches, shapes or numerical behavior; no model is imported or executed by this static workflow.

Source-authoring import/frontier/validate/generate and draft persistence have a 16 MB serialized-data budget, independently of the 80-file/2 MB source, 1200-node and 3600-edge analysis contracts. Canvas persistence keeps its 4 MB budget and shares immutable architecture facts between undo snapshots; reads reconstruct the exact original snapshots before validation. Browser local-storage quotas are host-dependent; use explicit server save/reopen for large drafts rather than assuming browser recovery succeeded.

Source provenance binds JSON number values consistently across Python and browser serialization: `0.0` and `0` represent the same JSON number. Actual value changes, boolean/string substitutions, source bytes and source/IR identities remain guarded; historical Python-only receipts remain readable with their original bytes.


## Reusable source adapters and Agent-authored rules

When capabilities expose `sourceAdapters`, read [adapter-generation-standard.md](adapter-generation-standard.md) and the runtime `adaptationRequests`/`coverage` response. A local opaque region may already have an automatic source-inspection subtree; `source-inspected` does not prove complete syntax or tensor semantics. A v1 `adapter scaffold → validate → register → preview` persists facts recovered by the existing checker and presentation aliases. It does not add a previously unsupported syntax rule.

When `sourceAdapters.agentRules` is available, an Agent can author a portable `archcanvas-source-rule/1` JSON template to recover new inspection structure. Read actual source/AST and saved `adapter rules`; follow `rule-validate → scaffold --rules → validate → register → fresh preview`. The independent interpreter matches AST patterns, selects genuine located AST nodes, checks containment and proves only its supported `expression-input` and `comprehension-iteration` relations. It does not call the old SourceStructure to approve an authored rule. Patterns and selectors should generalize across model, file and local-variable names. Verify a positive case, a renamed transfer case and rejected unsupported relations; do not accept a template solely because its JSON validates.

The resulting `archcanvas-source-adapter/2` binds embedded templates and applications to complete current source files/hashes, exact AST spans, entry/method, config, source parameters and return slots. Validation independently rebuilds facts; aliases and notes are the editable presentation layer. Registering a v2 instance requires at least one real match and saves its reusable templates under the service's `data-dir/adapters/rules`; no Python plugins execute. Scaffold can reuse them with `--registry`, and preview/managed-project preview automatically rebind available templates to the current corpus. Read `sourceRuleApplications`, `ruleDiagnostics` and truncation evidence to establish that the view actually used a rule. Unmatched or failed rules retain original graph facts. Rules reuse exact existing source cards where possible and attach only to corresponding opaque source regions.

Every changed corpus needs a new bound instance; stale instances never apply, while saved templates may freshly match changed source. A new parser or registry entry does not mutate an old immutable CanvasDocument IR. Reanalyze into a fresh document and preserve the old document/history. Rules carry actual loop/filter and enclosing branch contexts as source guards without selecting paths or inventing repetition counts. The bounded interpreter accepts only declared AST fields/indices and syntax proofs; stores, adjacent statements, branch ordering, shadowed comprehension variables, state-changing expressions and missing external implementations cannot become guessed dependencies.

These are source-structure view adapters, not typed module-catalog presets. Children have no tensor ports and `generationContract` remains null. Unsupported syntax beyond the rule DSL stays explicit until the formal interpreter gains a separately tested contract. The source-preserving generation workflow above uses independently located source anchors; an adapter check does not grant it a new rewrite contract. Source inspection, visual editing and a passing adapter check do not establish arbitrary graph-to-Python generation or runtime execution. Source-tree and installed Skill versions are independent; query actual capabilities before claiming rule support or bounded generation.

## Nested editing and durable reconstruction

When the runtime exposes the updated source-frontier workflow, branch/control wrappers open their immediate contents even for large models; nested module bodies remain progressively expandable. Use card `＋/−`, double-click, or “当前模型源码结构” to locate any retained source object. This library includes unopened descendants. Deleting an owner also removes hidden source/custom descendants; recovery restores the original source scope and cached local edits after save/reopen. Independent edge deletions and occupied boundary inputs remain protected. Deleting every source node retains its recovery library; use “新建空白模型” for an unrelated composition.

If `modelAuthoring.sourceFileEditing` is present, `POST /api/authoring/source-regions/read` accepts `{draft,regionId}` (draft or canonical source identity) and returns the selected complete Python file, source line range and `baselineDigest`. `POST /api/authoring/source-regions/apply` adds `baselineDigest,replacement` and returns a freshly analyzed `architecture`, `sourceEdit` receipt and static verification. Both requests use the normal session token. Read first: existing supported graph edits are included in the file. Unsupported pending edits block explicitly; restore or undo those edits instead of silently replacing them with old source.

For source-only branches or Agent-authored inspection structures without tensor contracts, edit their explicit Python source, inspect the new result, then open it with `/api/open` as a fresh managed document. Reenter editing from that document to obtain new source identities. Never attach the old draft's node mapping or generated-workspace binding to the new source. This supports explicit branch/module reconstruction without guessing tensor wiring or executing model code.
