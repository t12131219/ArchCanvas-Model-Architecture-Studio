# 每轮修改必须执行的回归与视觉验收

本文档是 Scene Visual Lab 的修改门禁。凡是改动节点布局、父子模块展开、层级投影、端口、路由、拖拽、画布坐标、SVG 渲染或案例数据，提交结果前都必须完成本文列出的自动化检查与浏览器视觉检查。

“仅在 Transformer 场景看起来正常”不算通过。共享布局和路由行为必须由通用逻辑实现，并在全部适用案例上验证；场景只负责声明结构和语义数据，不能在核心算法中增加按 `scene_id`、模块标题或截图坐标触发的修补分支。

## 1. 不可破坏的行为契约

### 1.1 通用性

- 核心布局、路由与拖拽代码不得针对 `classic-transformer`、`tensor2tensor-transformer`、`Encoder Stack`、`Add & Norm` 等具体案例或可见标题写条件分支。
- 新算法必须从节点边界、父子层级、端口、语义通道、展开状态和障碍集合推导结果。
- 新增案例和新增 `NodeDetailKind` 必须自动进入目录穷举测试；不能依赖逐案例补测试名单才能获得基础覆盖。
- 修复一个案例后，所有目录案例、经典 Transformer、Tensor2Tensor Transformer 和父子模块压力场景都不得回归。

### 1.2 原子收束模式

`atomic-bottom-up` 是默认模式，必须满足：

1. 先完成最深可见层的原子节点、真实端口和原子边，再自底向上生成父层投影。
2. 外层边从来源父模块反向追踪到唯一的最深可见原子出口，并从该真实端口直接连接后继模块。
3. 外部入边同样优先连接唯一的最深可见原子入口。
4. 被投影边替代的“子模块 -> 父框出口”和“父框入口 -> 子模块”桥线必须隐藏，不能出现重复短线、重复箭头或断点。
5. 跨父框投影边以前景绘制；路由时排除其所属父框，但仍避让父框之外的可见模块和展开子树中的无关叶子模块。
6. 只有在入口或出口无法唯一解析时，才回退到当前父框端口；回退必须确定、可重复，且不能产生孤立端点。
7. 不同 `relation` 或 `semanticChannel` 的边不能因为折叠而错误合并，尤其是 Q/K/V、残差、条件、mask、memory 和反馈边。

### 1.3 逐层模式

- `recursive` 保留为独立基线，不得偷偷调用原子收束结果改变其语义。
- 展开、收起、拖拽和静态导出在逐层模式下仍必须可用。
- 对逐层模式的修复不得改变原子收束模式的稳定原子身份、门户链和桥线隐藏集合。

### 1.4 路由与父框约束

- 外部边必须避让所有无关可见节点，包括已展开的 Encoder/Decoder Stack 等大型父模块。
- 当前详情层的内部边不得离开该层 `bounds`；不能从父框顶部、底部或侧边绕到框外再返回。
- 路由必须避让无关同级节点，以及展开子树中的无关最深可见叶子节点。
- 允许跨父框边穿过所属父框边界，但只能从解析出的真实入口/出口方向离开；所属父框不能被同时当作封闭障碍。
- 节点移动后必须重新计算受影响的端口和路径，不能保留穿过节点的旧折线。
- 无障碍时优先选择合法候选中的最短正交路径；不得出现先向目标反方向移动、绕远后折返的路径。
- 节点移动后，路径中不得残留同轴反向折返的“发卡”线段或从端口多长出的一截；路由候选必须在满足边界和避障后优先消除折返。
- 有障碍时才允许增加折点和长度；应优先使用父框内的边界走廊或障碍外缘走廊。
- 已有正常避让能力是基线。任何修改不得以解决跨父框问题为代价，使普通节点避让失效。

### 1.5 拖拽与无限画布

- 顶层节点的 `x/y` 不受 `paper_width`、`paper_height` 或旧的 12/32 像素纸张边距限制；尺寸最小值和最大值可继续受控。
- 展开父模块后仍必须允许所有顶层模块移动；多层展开不能锁死全视图交互。
- 展开父模块本身必须可以移动到负坐标或当前纸张右/下边界之外，展开派生布局不能把它弹回旧边界。
- 拖动未展开或已展开的详情子模块时，位置变化必须等于指针在世界坐标中的变化，并限制在当前父模块内容区内。
- 首次拖动不能把模块跳到最右侧；向左拖动不得被错误的绝对坐标、展开位移或父框宽度限制。
- 拖动父模块时，其整个可见子树与门户整体移动；子树内部相对位置和内部路由不得漂移。
- 缩放、平移和负坐标不得改变拖拽增量；普通滚轮和 Ctrl+滚轮都必须以指针为锚缩放画布并阻止网页滚动或页面缩放。
- 鼠标中键从空白处或节点上开始拖动都必须平移画布；左键拖动节点仍只移动节点。
- 画布及其全部子元素必须禁用文字选择和原生拖放，连续拖动不能出现文字选区或拖拽预览。

### 1.6 递归包含关系

- 父模块展开后，其包围盒必须包含全部直属子节点、展开子树、标题区和必要内边距。
- 全展开时不得只验证最外层场景边界。每个直属子节点及展开子树必须完全位于其直接父层内容区内，四边保留规定内边距。
- EncoderLayer/DecoderLayer 的根详情层不得重复绘制一层与展开 surface 等价的内部框；其层数和维度配置应保留为无框文字。对应 surface 是该层的包含边界。
- `frame` 必须显式区分 `containment` 与 `semantic-group`：只有 `containment` 框约束全部直属子节点并参与内容区推导、自动扩张和拖拽限位；未标注的旧 `frame` 按 `containment` 兼容处理。
- `Scaled dot-product attention / head`、`LSTM gates` 属于 `semantic-group`，只标识指定计算步骤，不得被布局算法当作父容器，也不得因无关同级节点或子模块展开而扩张。Attention 橙框仅包含两次乘法、Scale、Softmax 和 weights；Q/K/V 投影位于左侧，context、Concat、输出投影和 Output 位于右侧。LSTM 紫框仅包含门控算子。
- 展开任意子模块后，同级节点不能被挤出父框；父框增长与同级平移必须由内容包围盒自动计算。
- 移动已展开子模块及其相邻模块后，所有子节点仍位于父框内容区内，且连线不得越过父框边界。
- 收起后必须恢复由基础场景和已保存手动偏移确定的布局，不能累计展开位移。

## 2. 每轮必须执行的自动化测试

从 `studio/` 目录运行：

```bash
npx vitest run --exclude 'e2e/**' --exclude 'tools/export-p0-acceptance.test.ts'
npx tsc -p prototypes/scene-visual-lab/tsconfig.json --noEmit
npm run prototype:build
git diff --check
```

任一命令失败即视为本轮未完成。不得只运行新增测试后宣称通过。

### 2.1 必须长期保留的自动化覆盖

## 3. 每轮必须执行的浏览器视觉检查

自动化通过后启动或复用本地服务：

```bash
npm run prototype:serve
```

必须使用真实浏览器操作，不得只检查静态 SVG、DOM 数值或测试快照。每项操作完成后截图检查，并同时观察底部指标。若浏览器可能缓存旧构建，使用新标签页或查询参数重新载入后再判断。

### 3.1 固定检查场景

```text
http://127.0.0.1:4312/?scene=classic-transformer&expand=transformer-encoder
http://127.0.0.1:4312/?scene=classic-transformer&expand=transformer-encoder&drilldown=self-attention
http://127.0.0.1:4312/?scene=tensor2tensor-transformer&expand=tensor2tensor-encoder
http://127.0.0.1:4312/?scene=tensor2tensor-transformer&expand=tensor2tensor-encoder&drilldown=self-attention
```

如果本轮修改影响通用目录结构，还必须从六个模型目录中选择至少一个非 Transformer 多层案例复核，避免共享算法退化为 Transformer 特例。

### 3.2 顶层移动检查

1. 展开 Encoder Stack，记录检查器中的初始 `X/Y`。
2. 将整个展开模块向上拖过旧纸张上界，确认 `Y < 0` 且松手后不回弹。
3. 将其向左、向右、向下各拖动一次，确认坐标连续变化，不跳到最右侧。
4. 移动画布中的另一个普通模块，确认多层展开没有锁死其他模块。
5. 分别执行普通滚轮和 Ctrl+滚轮缩放，再次拖动，确认两者都围绕指针缩放画布，世界坐标增量仍正确，网页本身不滚动也不缩放。
6. 分别从画布空白处和节点上按住鼠标中键拖动，确认两者都只平移画布；左键拖动节点仍只移动节点。
7. 在节点标题、说明文字和画布空白处连续拖动，确认不会选中文字或出现浏览器原生拖放预览。

### 3.3 多层详情移动检查

分别展开 Self-attention、Add & Norm 和 Feed-forward 中至少两个：

1. 拖动已展开子模块本身，检查其子树整体移动且仍完全位于 Encoder Layer 父框内。
2. 拖动展开模块前后的同级节点，特别是 Dropout、Feed-forward 和另一个 Add & Norm。
3. 至少执行一次向左拖动和一次向下拖动；确认没有首次拖动跳到最右侧。
4. 检查所有相关箭头重新吸附到真实端口，没有穿过矩阵、算子或展开视图。
5. 检查残差线、mask/bias 线和主链均未越出当前父框。
6. 收起再展开，确认手动偏移和派生扩展位移没有混淆。

### 3.4 全展开与全收起检查

1. 在经典 Transformer 中依次展开 Self-attention、Add & Norm 和 Feed-forward，确认新分支不会收起已有分支。
2. 点击“全部展开”，确认当前场景所有顶层详情模块递归展开到没有可展开子模块的原子叶子。
3. 检查每层全部兄弟展开框均在直接父层 surface 或显式 `containment` 内容区内且互不重叠；EncoderLayer/DecoderLayer 使用根详情 surface 作为包含边界且不得出现重复内部框，层配置文字必须保留；`Scaled dot-product attention / head`、`LSTM gates` 等 `semantic-group` 只框住声明的计算步骤，不能因 Q/K/V、输出链或展开子模块而扩张；外部路由不穿越因递归增长而变高的父模块。
4. 点击“全部收起”，确认顶层详情与所有嵌套分支同时恢复折叠；再次全部展开后结果应一致。
5. 对经典 Transformer、Tensor2Tensor Transformer 和至少一个非 Transformer 多层案例分别执行以上操作。

### 3.5 原子收束与逐层 A/B

对同一展开状态分别选择“原子收束”和“逐层”：

- 原子收束：外层线必须直接连接最深可见真实端口；被替代桥线不可见；跨父框线在前景且避让无关模块。
- 逐层：保留父框入口/出口语义，展开和拖动仍正常，不能出现由原子模式隐藏集合造成的缺线。
- 两种模式：均不得有孤立箭头、重复箭头、父框外绕行或无关节点穿越。

### 3.6 最短路径检查

1. 将 Source padding mask、attention bias 或任一条件模块拖到目标模块下方。
2. 确认连线切换到相互面对的最近端口，优先采用直接线或最短合法正交线。
3. 确认路径没有先向反方向伸出再折返，没有沿父框远端绕行，也没有为了避让所属父框而穿越其他模块。
4. 再把模块拖回上方，确认端口和路径可逆更新。
5. 移动 Q/K/V、Linear 或其他相连节点，确认端口附近没有同轴折返、悬空短截或多余长出的线段。

### 3.7 视觉通过标准

- 节点穿越、重叠、净距违规和端口拥挤必须为 `0`；若某个历史场景已有非零指标，必须证明本轮未增加并记录局部检查结果。
- 外部与内部路径的可见断点、重复桥线和非法父框越界均为 `0`。
- 模块、标签、展开按钮、选择框和箭头之间没有新增遮挡。
- 所有模块在目标缩放级别下可点击、可拖动、可展开和可收起。
- 控制台无运行时错误，SVG 不为空，点阵背景、缩放和平移仍正常。

## 4. 每轮完成记录

完成修改时，应在任务回复或变更记录中至少报告：

- 自动化测试数量及结果。
- TypeScript 与生产构建结果。
- 实际检查过的场景 URL、层级模式和展开层级。
- 实际执行的拖动方向，包括是否验证负坐标和向左移动。
- 视觉指标及发现的剩余已知问题。
- 若跳过任何项目，明确说明原因；未说明的跳过视为未完成验收。

本清单是最低要求。修改涉及更多层级、路由或交互状态时，应扩大测试矩阵，不能用本清单限制必要的额外检查。
